# LH 历史位置

本页只保留 LH 作为早期实现与设计牵引的历史记录。LH 不是当前数学语义的第二套定义；当前对象、函数、事件和继续规则以三份正典教材与语义锚点为准。

## 1. LH 实现提出的问题

旧 C++ Connectome 使用 input cortex 与 output cortex 两套状态空间，并通过 `inputA`、`outputA`、`ioA`、`oiA` 等结构连接它们。外部 token 输入后运行有限个 internal tick，指定输出节点的值被保存，再由 Pronounce 汇合读出。

旧节点处理把几件事情放在同一执行流程中：接收局部输入、结合 local hidden 形成候选激活、由 selector 决定保留哪些激活、更新归一化或激活量，以及可选的 `clear_after_activation`。hidden 既有加法累积，也有局部 KV 记录；KV 保存的是实际送达该节点的历史，而不是全图公共历史。

这些实现细节后来促成了几个需要在数学上分开的问题：

- 收到消息与被选择是不同的覆盖；
- 记忆的写入、读取、清理和跨步保存需要分别规定；
- 选择历史可能影响后续路由，必须成为显式状态；
- 内部处理过程与外部读出不必使用同一个时钟或同一个事件。

## 2. LH 对后续语义设计的牵引

LH 的实现先于完整的数学讨论，但它提供了后续 Graph、TimedDAG 和 SettleGraph 需要回答的具体约束。当前教材中的候选状态、选择描述量、局部控制、`Next`、`Full`、选择历史和 continuation，正是把这些混在一起的实现动作拆成可检查的数学坐标。

这是一条设计来源关系，而不是实现到教材的自动证明关系。旧 `internal tick`、CHAL、selector 的具体执行顺序，以及旧候选激活是否在昂贵计算前已经可得，都不能仅改名后当作当前节点契约；若要采用它们，必须按当前教材重新声明函数类型和依赖。

## 3. 当前边界

LH 的代码、参数、局部状态和旧对拍结果不构成当前 Tide 实现标准，也不代表下游实验仓库的最新状态。它们只用于说明设计问题从何而来，以及为什么当前语义要求显式 owner、明确状态边界和可复核的 continuation。
