# 从 LH 异时输出到 HB 多跨度候选

本页收拢 2026-11-13—15 的设计讨论，保留问题、取舍和当前落点。它不将拓扑可达性当作训练质量或设备性能证据。形式定义分别位于拓扑、局部模块和实例；四份正典及 tide-core-5 核心接口保持。

## 1. 原始问题与现在的分支

原始需求是一张真正允许长短加工并存的网络：一些任务可使用较早输出，另一些需要更深加工；长短通路在早期、中间和后期反复合作，持续输入时不要求每轮等全网结束。输入位置与逻辑时间分开，Tide 已为异时到达与持久状态提供相应语义。

同时希望分布式扩展、局部通信和稀疏参与，并让已知输入窗口的 prefill 有可预期的组织方式。这推动了严格区域分层的 HB 主候选；LH 继续探索有区内消息或反馈的一般情形。

| 分支 | 当前落点 | 主要比较 |
|---|---|---|
| 原 HB-Lattice | [既有拓扑](../../topologies/hb-lattice.md)及实例保留 | 基础展开收拢、相邻层稀疏邻域、对齐时间 |
| HB-Timed | [多跨度图](../../topologies/hb-multiscale.md)，单位边时延 | 严格区域分层且有多种消息时延 |
| 同图对齐 | 同样端点，跨度时延；区分对齐 TimedDAG 与严格 Settle 时间编码 | 固定连接比较到达汇合方式 |
| 无特殊 hub | 删除 H 节点及 DH／HH／HD，保留完整 DD 子图 | 普通通路独立承担加工与交换 |
| LH-DAG | [双侧层次图](../../topologies/lh-exploration.md)，区内边，无反馈 | 一般 TimedDAG |
| LH-PDG | 同一 LH 图加输出 hub 到输入 hub 的正时延边 | 有限切面与持续反馈 |

新的 HB 连接更细致，但不是原 HB 的数值等价替换；两者保留各自名称。多跨度连接并不只能用于 Timed：对齐版仍有多尺度信息通路，但不能再借不同路径填充同一输入间隔内的全部输出相位。相同端点有利于控制结构差异，也可能使对齐版承担原本为频繁异时交换设计的冗余通信。旧 HB 提供另一种更直接的对齐基线。

“无 hub 尚未完整绑定”曾指临时图已构造、正式局部组合尚未入库；并非它缺少可表达性。现在它直接使用[主绑定 K 或 S](../../instances/hb-multiscale-weighted-message.md#2-两类记忆与三个主候选)，与含 hub 的图使用同样接口。

## 2. 扩大之后如何分工与合作

扩大之后，怎样让各部分既有分工，又有足够的信息合作，仍是真实问题。全量传播会增加重复加工和通信；过少交换可能丢失关键信息，并把过高要求交给路由。把每相位独占一条分支，再在少数节点集中融合，会重新形成压力集中。

当前设计用三种可分开的机制回应：普通 DD 通路携带局部细节，邻域重叠和跨组置换让它们逐步合作；hub 通过 DH 收集压缩背景，通过 HH 跨组、跨层交换，通过有限 HD 探针送出钩子。摘要可帮助下游依据已有细节和自身记忆进行选择，但不会自动补齐未收到的细节。跨组不是独立神奇算子，而是把来自不同粗位置组的消息送到相遇处；真正融合由 Agg、记忆和内容函数完成。

这里只手工设置 D／H 两类节点。主通路、邻域、跨组、跳层首先是连接类别；来源聚合可区别这些类别，不因此增加多套节点角色。结构规定可用信息和最低通信待遇，学习决定如何利用它们。纯学习角色更灵活，但不能保证学出必要的通信能力；完全手工专职更可控，也更容易限制泛化和增加算子碎片。当前折中是少量结构性角色、统一消息接口、同族可共享参数，暂不增加 hub 专用汇总函数。

同一位置的四个 hub 各收一部分、互相通过后续层传播；不是一份全局摘要的四次复制保证。它们可学到重复表示，也可分工，拓扑不能预先证明哪种结果。无 hub、稀疏放置、不同共享强度正好用于检查这种投入是否有价值。

## 3. Hub 组织、密度和内存

当前图示的每个位置含一个 16 节点 D 区和一个 4 节点 H 区；完整实例另给 32+4 配置。不是每个区域都有 hub。最早的 128+4 图把同位置 D/H 混在一区，二者的“位置”对应关系保持，分区发生变化。

三种分区的条件性排序仍是：独立小 hub 区优先，singleton 次之，混合区作为对照。group 可以在几个 hub 之间权衡发送，不让普通节点的大量描述直接进入 hub 的共同选择；singleton 适合更强调独立控制或独立响应的情形，可以排第一；mixed 提供同次共同选择，但也增加描述依赖和预算相互影响。固定通过时 group 的数值分配已经解耦，不应仅凭区域数量推断仍有竞争或必须物理同步。

部分位置放 hub 已有明确候选：按 $(\ell+p)\bmod2$ 交错保留，删除其余 hub 及关联边，普通子图不变。它用更少的摘要通路换较少节点与通信，不把剩余 hub 自动改为服务所有被删除位置。全位置、半位置和无 hub 可比较，但本次交互图主要展示全位置 group，并明确标记范围。

Hub 常接收消息且较少，SSD 的固定状态有理由优先考虑；普通节点可以用有限 KV 保存细节。全 KV 与全 SSD 是两个统一算子对照。因此主候选收敛为 K／S／X 三组，其他既有模块继续作为研究目录；不要求实现全部笛卡尔积。较大的 hub 入出度是有限、已量化的代价，不能仅以“有界”一词掩盖实际扇入、投影和通信成本。

## 4. 异时混合与物理响应

假设输入间隔为 4，旧输入的时延 6 通路和新输入的时延 2 通路在同一节点相遇。它可能让新信号利用旧问题的深加工，也可能造成时间归属模糊、干扰或过时信息。Tide 定义其准确的聚合与历史顺序；优劣依任务与训练决定。没有必要先增加完整 token 来源集合。Pos 编码处理时间，不能把它误称为混合内容唯一的来源位置。

对齐版把同源消息集中到一次作用，改变写入次数和竞争对象；它仍通过 KV／SSD 历史混合此前输入。严格区域分层保证的是已知窗口的区域求值顺序，不消除节点的状态依赖，也不把最短逻辑路径直接变成物理时延。

三种容易误解的等待见[实例 §5](../../instances/hb-multiscale-weighted-message.md#5-精确求值与输出依赖)：较早状态更新、同区描述共同分配、上游选择决定消息是否存在。只等本次完整依赖；不等不存在的 Full，也不等与本输出无关的晚路。固定模型已经定义这些依赖，无需新增“快速输出就绪”规则。全窗口 prefill 与流式 decode 可以采用不同求值组织，只要保存相同参考语义。

Pronounce 仅作为语言任务的下游头提及；其聚合周期、输出组织及自回归接入由下游定义。无环图在持续输入下也可持续输出，有环图还可能在输入停止后继续活动。

## 5. 本轮闭环与仍需实验证据的事项

本轮形成了共同 HB 拓扑与三种时间绑定、无 hub／半位置 hub 的明确图、三种区域划分、角色上下界及导数、三组主局部绑定、LH-DAG／PDG、参数共享方案和[离线交互公式面板](../../explorers/hb-timed/README.md)。生成器和数学核对属于维护源，HTML、图片及报告由登记构建重建。没有修改旧模型默认值或宣称下游已采用。

后续真正需要证据的是：相位覆盖是否转化为有用输出，分区是否减少实际等待，共享／适配的容量是否足够，hub 摘要和普通局部细节是否互补，稀疏是否节约准备与 Full 的总工作，以及准确性与时延吞吐的折中。这些问题保留在设计记录，具体训练与系统实验属于下游。本仓库不为约 3% 增加统一统计规章，也不引入旧历史公平 selector、累计 token 预算、自主唤醒、逐边载荷或动态检索。
