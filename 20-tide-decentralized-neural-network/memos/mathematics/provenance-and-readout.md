# 来源、聚合与读出：压缩以后还必须知道什么

本页保留旧稿中有关消息身份、依赖来源和安全聚合的讨论。教材中的原子、时间纤维、端口及完整切面是当前语义；来源证书和额外读出设计是可选工具，不能隐式增加核心字段。历史出处为 Git `133d638` 的 `tide-mathematical-foundations.md` 第一部分 §2、§3.6 与第三部分。

## 1. 消息身份不等于输入归属

一条消息可能融合多个输入位置的影响。至少区分：

| 对象 | 回答的问题 |
| --- | --- |
| 消息标识符 | 这是哪一次发送产生的哪条记录？ |
| 逻辑时间 $\theta$ | 它在哪个时间纤维中参与处理？ |
| 输入来源集合 | 哪些外部输入可能影响它？ |
| 读出端口与时间 | 哪个可观察输出使用这个值？ |

当前原子本身保留外部端口或内部边身份。一个自定义聚合函数可以只取值的和，也可以利用来源；这属于函数选择。不能先丢掉边身份，再假定未来还可以无成本恢复。

“属于 token $t$”通常只是应用层标签，不是一般消息的唯一数学归属。跨 token 融合后，强行指定唯一 owner 会丢失其他来源；也不能用这个标签代替逻辑时间排序。

## 2. 一个安全聚合的充分条件

设完整输入对象属于集合 $X$，下游可观察结果由 $F:X\to Y$ 给出。要把输入压成 $\alpha:X\to Z$，充分且必要的条件是存在 $\bar F: \alpha(X)\to Y$，使

$$
F=\bar F\circ\alpha.
\tag{1}
$$

等价地，任意 $x,x'$ 若 $\alpha(x)=\alpha(x')$，就有 $F(x)=F(x')$。

**证明。** 有式 (1) 时，两者应用同一 $\bar F$ 得同值。反过来，对 $z\in\alpha(X)$ 任取满足 $\alpha(x)=z$ 的 $x$，令 $\bar F(z)=F(x)$；上述条件保证定义与选择无关。□

这个结论只回答指定观察函数 $F$。例如两条消息值为 $(1,2)$ 或 $(2,1)$，求和都为 3。若下游只读和，压缩安全；若下游问“第一来源是什么”，就不安全。

对于有状态模型，$F$ 必须包含未来需要的状态，不能只包含当前 logits。更实用的局部条件是：给定状态抽象 $\alpha:S\to Z$ 和输出抽象 $\beta:Y\to\bar Y$，如果

$$
T(x,s)=(y,s')\quad\Rightarrow\quad
\bar T(x,\alpha(s))=(\beta(y),\alpha(s')),
\tag{2}
$$

则对输入长度归纳，压缩状态可精确继续产生同一抽象观察。此为 transition 的商语义；它不承诺重建原状态。

## 3. 来源集合可以保守传播

把外部记录标成 $(i,k)$，其中 $i$ 是输入端口，$k$ 是该端口位置。可以在数学审计中为每个值附加有限集合 $D$：

- 外部输入的集合包含自身 $(i,k)$。
- 常数和与数据无关的初态可取空集。
- 一个函数输出的集合可取全部实际自变量来源集合的并。
- 条件选择也要计入影响分支决定的输入；只跟踪被选值的数据路径可能漏掉控制依赖。

由事件 DAG 上的归纳，这给出保守的依赖集合。它未必最小：$x-x$ 的输出恒为零，简单并集仍会记录 $x$。若要声称“精确依赖”，须另定义函数对输入变化是否敏感，不能把传播得到的上界称为精确因果解释。

这样的证书可用于检查某个读出只依赖允许的输入前缀。多输入端口时前缀通常是一组每端口边界，不能未经定义缩成一个 token 编号。教材依赖逻辑时间和正时延证明的因果性，不需要先添加这些证书。

## 4. Readout 与未来上下文

在固定读出时间，参考语义应声明使用哪些端口记录，以及如何合并它们。实际完成慢，不允许补改已经定义的过去输出。

“等待本次所有声明分支汇合”与“较晚分支只影响未来上下文”是不同模型：前者有当前输出依赖，后者必须沿正时延消息进入未来事件。二者都不能用墙钟截止时间决定数学可见性。

TimedDAG 的不等长路径可以让多个输入位置在一个逻辑时间纤维中汇合。此时一个 Full 调用的输入是整个聚合结果，不能再把它任意拆成彼此独立的 token 子问题。若要训练自回归模型，还需声明 token 输入时间、读出时间及允许的因果前缀。

## 5. Cache 与压缩的三种不同主张

1. **精确状态表示变换**：满足式 (2)，例如去掉以后永远不可读的临时量。
2. **近似压缩**：允许输出或状态误差，须给输入域、误差度量及跨步累积方式。
3. **蒸馏成另一模型**：通过数据拟合旧行为，质量由实验评估。

KV cache 不是全部计算历史，而是具体 attention 契约的持久状态；SSM 状态是其自身递推的精确状态。二者不能仅凭“都概括历史”就互换。实际 cache 删除和消息聚合的证据由实现仓库维护，数学上的问题始终是：被合并的差异会不会在未来被观察到？
