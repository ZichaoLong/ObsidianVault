# 执行与成本：正确、可批和实际更快如何分别判断

本页整理可复用的成本问题，不维护任何实验仓库的当前完成度、后端接口或硬件配置。来源为 Git `133d638` 的架构旧文第四部分、训练部分的执行讨论及 runtime 旧文。

## 1. 四个问题分别需要证据

| 问题 | 需要什么 |
| --- | --- |
| 算的是否是同一模型 | 输出、状态、选择、消息与 continuation 的数学对应 |
| 有限切面能否完成 | 教材有限性结论，以及局部全函数的终止实现 |
| Full 能否按节点批量调用 | 完整输入的可用性、控制依赖、合法 batch witness |
| 是否实际更快 | work、span、存储、通信及指定硬件上的测量 |

集合论全函数不自动附带算法。有限函数作用数也不自动产生低 span。节点只调用一批，还可能需要较长控制扫描；反之，把串行循环装进一个 kernel 也不会消掉内部依赖。

## 2. 常用局部执行方式

| 方式 | 必要的结构说明 | 主要风险 |
| --- | --- | --- |
| Map | 输入坐标已经独立确定 | 隐藏可变状态使“独立”失效 |
| Scan | 预先可得、紧凑封闭且便宜的转移摘要 | 矩阵变稠密、组合比原步骤昂贵 |
| Causal bulk | 专门算法与逐步契约等价 | 掩码、位置、历史 cache 或数值次序不一致 |
| Ready-set packing | 全部语义前驱就绪，没有读写冲突 | 物理队列就绪不等于候选集合已关闭 |
| 顺序 fallback | 明确执行相同的参考函数 | 关键路径可能随窗口长度增长 |

具体证明见 [kernel chunk 组合](../mathematics/kernel-chunk-composition.md)。SCC、region 和 macro 是封装范围，不是另一种并行算法。尤其不能任意把区域收缩后就假定商图无环。

## 3. Work、span、通信和内存

对已经确定粒度及成本的有限执行 DAG，令 $W$ 为全部操作成本之和，$S$ 为最长依赖路径成本，$P$ 为处理器数。任何执行至少需要

$$
T_P\ge\max(W/P,S).
$$

在理想的独立任务、无通信代价的列表调度模型中，有 $O(W/P+S)$ 上界；实际机器还受内存带宽、通信和 kernel 形状约束。

稀疏工作不能只计算 ActiveCompute。账本至少包含：输入分发、所有实际接收者的 Agg/Upd/评分、selector-history、Next、Full、消息构造、读出、边界状态和反向所需快照。BO 中未选节点的状态更新仍有成本。

还应分别记录峰值状态、跨界在途消息、KV 增长、临时 packing、activation 保存与通信字节。图上度数有界只限制单次邻接数量，不保证物理距离短或总传播 hop 数少。

## 4. 语义节点与执行 tile

一个有私有状态的数学节点，可以由多次 kernel 执行；多个节点、时间和序列的独立作用，也可以整理成 grouped GEMM 或 packed attention。两种粒度不必一一对应。

旧稿设想 CPU 处理紧凑分数/history，加速卡处理大张量。这是一种后端选择，不是语义要求。合理性取决于一次数据传输能覆盖多少控制工作、控制扫描是否成为瓶颈、是否能与其他区域计算重叠。对每个时间点来回同步通常增加关键路径；将一段时间的控制集中处理，则需先满足教材给出的输入可用条件。

复用底层存储时，仍需保持每个 Full 作用的正确输入版本。把 Next 清理提前覆盖掉尚未消费的快照，或者让两序列共享 mutable history，都会改变结果。

## 5. 数值稀疏不等于可获利的跳算

近零值、精确零值、硬件支持的结构化零块，以及完全未激活的模块是不同对象。跳过近零值通常改变数值函数；精确零也可能过于不规则，无法节省时间。

在一个简化的串行开销模型中，稀疏方案有收益需满足

$$
T_{\mathrm{detect}}+T_{\mathrm{pack}}+T_{\mathrm{index}}+T_{\mathrm{sparse}}
<T_{\mathrm{dense}}.
$$

实际有流水重叠时应测量总关键路径，不能机械相加。固定逻辑邻接若映射到远距离设备，仍可能产生昂贵通信；节点过细会使大矩阵拆成许多低利用率小工作。

## 6. 中间粒度假设

一个有价值但未证明的研究问题是：是否存在某种节点粒度，同时满足

- 被跳过的工作足够大，超过控制、packing 和通信开销；
- 单次换路的贡献变化足够可控；
- 私有状态与局部路径能被训练使用；
- 在匹配资源后质量至少达到有意义的基线。

这是关于具体任务、规模、数据和硬件的存在性假设。某个平台上可能没有这样的粒度，不说明数学框架无效；某个模型上出现收益，也不证明所有局部图优于 dense 或 MoE。

## 7. 实验平台应保存什么

一份可审查结果至少注明代码 revision、上游语义版本、输入域、配置、dtype、机器、对照标准及失败范围。比较输出之外，还需比较边界状态和后续继续；对训练另外比较梯度及随机状态。

基线可采用原模型继续训练、成熟 flat MoE、固定路由和匹配容量/资源的简化结构。多机制完整候选可用于寻找正面信号；单机制归因需要 matched control 或 knockout。调参预算、随机种子与数值容差由实验平台公开，不在上游备忘复制一份易变门槛。
