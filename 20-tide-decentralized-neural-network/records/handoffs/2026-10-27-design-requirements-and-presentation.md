# 接续：Tide 设计需求、架构关系与展示内容

本页为没有此前对话历史的新会话提供工作入口。仓库为 `/home/zlong/ObsidianVault`。它记录截至 2026-10-27 已确认的目标、材料状态与尚待讨论的解释；后续以当前仓库及用户的新说明为准。

## 当前要开启的工作

先梳理**去中心化与稀疏化的首要需求、细化要求、共同架构和局部语义之间的关系**，形成有依据、可讨论的设计说明，为之后的展示稿提供内容。

用户希望理解：当前上层架构如何回应这些需求；局部设计或实现的迭代，又怎样推动上层区分接口、状态和依赖。Mem 是否承接某项细化需求，是用户提出的一个待梳理例子。

最近已同意的下一步是：明确希望分散哪些信息与决策、减少哪些计算与传播，再逐项检查当前机制提供了什么、付出了什么。当前任务以设计梳理为中心，展示稿是后续用途。

## 已确认的方向

- 用户明确说明：“Tide 本身的最大设计需求，就是去中心化＋稀疏化。”这项优先级已经确定，具体范围仍需细化。
- 本仓库首先是数学与语义上游。正典是面向首次接触 Tide 的数学读者的教材，保持简洁的数学行文、统一符号和可追溯接口；下游实现可以按这些定义核对。
- 展示面向首次听众，可从熟悉的顺序连接出发，按需要借助 residual 旁路。沿已有理解引出新内容，尽早完成一次计算，随后展开候选。
- 每项关键设计应有可理解的需求或目的，并通过机制与例子展示其作用。一个需求可以有多种解法，同一设计可以服务多个目标。
- 共同框架允许不同局部语义。带权消息是一条具体支线，KV、循环记忆、评分与发送规则又是在该支线内的选择。各专题可独立讲授，入口说明所需前置与输入输出。
- 展示采用讲者控制的逐步显露，保留已讲结构的位置和名称。短动画服务于消息传播、写入与跨次保留；每一步都可停住说明，静态导出也能顺序理解。
- 区分当前设计理由、真实形成过程、教学顺序。历史叙述需要来源，讲述顺序可以按理解需要重排。
- 区分数学保证、机制判断、外部结果与 Tide 实测。定义提供的能力和任务效果分别说明。
- 版本、下游采用及修订过程独立记录；面向读者的入口与教材直述内容，避免反复使用“不是……而是……”界定立场。

这些原则已经整理为[展示内容技能](../../skills/tide-presentation-writing/SKILL.md)，并与[数学写作技能](../../skills/tide-math-writing/SKILL.md)互相链接。新会话应直接读取文件，不能假定它们已被全局安装或自动加载。

## 尚待澄清，不能当作定论的内容

| 待澄清项 | 当前讨论的起点 |
|---|---|
| 去中心化的对象 | 可分别讨论信息与状态归属、决策范围、固定主干或汇聚点的角色、设备执行、学习规则。用户尚未逐项指定要求和优先级 |
| 稀疏化的对象与尺度 | 分别考虑连接、候选事件、完整计算、消息传播及实际成本；尚未指定统一指标或数值目标 |
| Mem 的需求来源 | 可从“选择参考本地历史”“不同记忆提供相容描述”等理由解释当前接口，但这不是已经核实的历史发生顺序 |
| 架构形成的具体因果链 | 上层需求与下层行为可能双向牵引；每个历史判断需用户说明、原文、提交或实验依据 |
| 收益与优先方案 | 尚无本次工作的新训练或性能证据，也未因这些讨论选定某种局部函数为唯一推荐方案 |

较早提出的“约 14—16 页、20—30 分钟”“Markdown 内容源、离线 HTML 与 PDF”等只是形式建议；时长、页数与技术栈按实际任务决定。

## 第一阶段建议产物

先在设计备忘的职责下形成一份简短的“设计需求与架构关系”讨论稿。文件名与具体组织可自行决定；已有局部设计总览主要讨论带权支线，新增梳理应补足总体层面的关系。

按实际问题组织，必要时用一张表连接：

> 目标或需求 → 明确场景与参照 → 当前机制及定义出处 → 已有能力与条件 → 代价、替代方案和待确认项。

整理内容时：

1. 先读取两个技能、教材入口与接口索引；按问题进入正典、局部教材和设计记录。引用的具体机制须回到原定义核对。
2. 区分已由用户确认的目标、当前定义的事实、设计解释和待验证假设。现有备忘与旧记录也可能需要修正，不能只汇总原句。
3. 用少数具体关系检验解释是否清楚，例如“区域协调怎样服务去中心化”“选择性 Full 实际省去哪一部分工作”“选择参考历史怎样连接状态、Read、Mem”。同时保留相容的替代构造。
4. 对影响主线的未知意图提出少量关键问题；可以独立核对的材料继续推进。不要把全部细节一次性交给用户回答，也不要将暂定解释写成已确定需求。
5. 先交付可讨论的设计梳理与剩余问题，再据此安排展示主线。涉及数学定义的改动须独立论证；不以教学动机代替定义或证明。

用户希望三种载体配合：对话澄清目标与取舍；文档保存当前解释及依据，历史另记；展示稿选取适合首次听众的理解路线。技能保存可复用的组织原则，具体设计判断留在相应说明中。

## 解释时特别保持的语义边界

- 去中心化与稀疏化是设计需求。框架容许单一区域、稠密选择等配置，具体达成程度按模型的信息依赖、区域范围、拓扑与函数判断。
- 逻辑时间描述到达、状态顺序与读取坐标；演示动画的播放速度或设备执行时间不替代它。
- P/S/U/F 是作用阶段：P 中形成候选状态，U 确定本次计算快照与下一持久状态。Full 读取计算快照。
- 正典的状态与 Read 保持一般性。Mem 四元组属于带权支线；Read+、全部候选保留接收更新、标量控制、同值广播也是具体绑定的规则。
- 区域发送总强度、激活节点数、消息数和设备工作量分别计量。未激活的候选仍可能承担准备、读取与状态更新。
- 具备本地状态或条件选择，可以支持进一步设计；学习质量、物理部署和性能收益仍需相应条件与证据。
