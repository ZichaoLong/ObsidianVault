# 有界通信、输入扩散与输出收拢的来源

本页核对“不要一个节点与无界数量的节点进行通信”在旧文中的依据及其去向。当前需求解释见[设计讨论稿 §3](../../memos/design/design-requirements-and-architecture.md#3-需求共同框架与局部选择)，可达范围推导见[附录 A](../../memos/design/design-requirements-and-architecture.md#附录-a固定端口下的可达范围)；旧文的命名、模型候选和更强成本目标按各自历史版本理解。

## 1. 本轮用户确认的范围

2026-10-28，用户先在 token 输入、下一 token 预测的有限输入输出边界下，说明内部去中心化与容量扩展需要逐步扩散和逐步收拢，并指出一项真实需求：

> 不要一个节点与无界数量的节点进行通信。

这与此前确认的信息与决策局部性、参与节点和连接数量优先，以及全区域参与可以接受共同构成当前目标。[后续关于假设与实验的讨论](document-revisions.md#2026-10-28端口规模假设与实验优先级)将端口边界与 Next Token 预测上的单输入单输出选择分开；[固定端口扩展的澄清](document-revisions.md#2026-10-28固定端口扩展与外部接入接口)明确：固定端口后的扩展需要扩散与收拢，不同任务或模型可以另选端口数量，二者同时成立。关于无界输入输出的第三点，用户随后明确其仅用于[范围外答疑](document-revisions.md#2026-10-28无界端口仅作为范围外答疑)，不属于 Tide 的考虑范围。

## 2. 旧文中的明确表述

在提交 `133d6383f1d69d986955c23d516aaef9a9529734` 保存的旧架构文档中，[§1.2.1「从目标约束到有界多跳扩展」](https://github.com/ZichaoLong/ObsidianVault/blob/133d6383f1d69d986955c23d516aaef9a9529734/20-tide-decentralized-neural-network/tide-model-architecture-and-training.md#L72-L95)把以下三项列为当时的原始要求：执行期间固定的空间拓扑、单节点成本统一有界、可达且可利用的总容量持续增长。随后区分度界、多跳扩展和额外的稀疏激活要求。

其中原文写道：

> 固定空间拓扑本身不推出度有界；度上界来自单节点成本上界和“每条直接连接都占用实际资源”的成本口径。

同段进一步要求：

> 这里把入口、router、广播和 merge 都计入成本，不能把一步全局访问当作 Graph 外部的免费服务。

原文使用固定入口数、最大 fan-out 和传播半径的几何级数计数说明多跳扩展，并明确这个结论不指定某一种规则树。它足以证明这项设计理由已经存在于该历史版本；本次没有据此确定最早提出的时间。

同一文档的 [§10「输入扩展与输出收拢」](https://github.com/ZichaoLong/ObsidianVault/blob/133d6383f1d69d986955c23d516aaef9a9529734/20-tide-decentralized-neural-network/tide-model-architecture-and-training.md#L694-L712)画出输入、区域与单元扩展、内部计算、逐级收拢、读出和输出的链条。原文声明：

> 扩展树和收拢树的深度、fan-out 与 merge 规则都属于静态图。

它还将 HB-Line reference 向全部初始 site 直接注入的做法说明为简化代码的参考规则。当前 HB-Lattice 的定义须从[现行拓扑](../../topologies/hb-lattice.md)核对，不能沿用旧 HB 名称判断构造相同。

## 4. 当前可采用的结论与边界

- **已确认需求：** 内部信息与决策局部，单节点直接通信对象数量不随网络扩展无界增长，优先限制每次参与的节点和连接数量。
- **边界配置与实验选择：** 先固定所讨论模型的输入输出配置，再分析保持该配置的内部扩展；其他任务或模型可使用不同端口数。实验优先使用 Next Token 预测上的单输入单输出。
- **历史事实：** 旧文确有度界、多跳扩展和输入扩展／输出收拢的论证，也曾采用所有单节点总成本统一有界的更强表述。
- **当前推导：** 在端口数和直接邻居数保持有界时，增加结构上可达并能影响输出的节点数量，需要增长传播距离；不同有限端口配置分别使用同一计数。
- **尚未确认或验证：** 更强的总成本要求是否整体沿用、单节点状态与消息宽度的规模约束，以及新增节点容量能否改善任务效果。度界本身不提供这些结论，也不指定唯一拓扑或每次输入的总工作量。
