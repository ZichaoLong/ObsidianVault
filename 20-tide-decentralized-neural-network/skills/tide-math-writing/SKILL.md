# Tide 数学文档写作

## 目标与范围

按当前请求和对话上下文确定本次任务、修改范围与交付方式。本技能保存可复用的编辑原则；具体文件的整改清单属于当次执行安排。

本仓库首先是数学与语义上游。教材面向初次接触 Tide 的数学读者，同时作为架构设计语言，牵引下游实现与研究。可假设读者理解基本不等式、元组、函数和优化问题；Tide 的对象、术语和接口须在文中定义或从明确的上游定义引入。

使读者能够顺序回答：正在构造什么，已有输入是什么，为何引入这个量，它在哪里使用，可以替换哪一步，当前结论适用于哪个范围，最终返回什么。按内容决定重写或局部调整。

## 文档分工

先确认文档承担的任务，再决定行文顺序和细节深度。

| 文档职责 | 主要内容 |
|---|---|
| 上层教材 | 自足的数学框架、语义、参考计算与性质；下游文档向上引用这些定义 |
| 局部架构 | 规定接口、共同规则、可替换的位置，以及局部条件如何推出组合性质 |
| 局部模块 | 实现接口的具体函数、适用条件、完整例子及局部性质 |
| 拓扑与时间约束 | 连接、区域划分、时间与传播结构，独立于具体局部计算 |
| 组合实例 | 选择已有定义形成完整绑定，说明采用哪些性质及其条件 |
| 研究备忘录 | 设计直觉、理论或实证依据、优缺点、限制与待解问题 |
| 实验文档 | 可选的实验设置、比较方法、观测量与推进建议 |
| 参考与记录 | 接口查询、实现核验、学习资源、版本差异与下游采用状态，按各自用途组织 |

教材正文集中叙述数学内容；较长证明可放附录。计算系统术语在适当的附录或参考文档中给出数学定义及对应。版本变更和采用状态独立记录。实验安排与局部函数定义分开，具体推进由当次研究目标决定。

## 定义、层级与阅读顺序

### 先让读者知道正在定义什么

对用途或含义不易理解的定义，先用简短、易懂的话说明它是什么、为何引入或随后用在哪里。优先使用读者已经理解的对象和操作；新术语的名称、类型或公式本身未必足以解释其作用。

例如，可先写：“下面几种发送规则先计算各节点的归一化份额，再按不同方式得到发送强度。先定义共同使用的份额，再分别给出发送公式。”随后定义份额及各规则。

定义先于依赖它的计算和推导。导入可以提前交代目的和结构。需要先展示整体时，可先给出对象或函数的签名、输入输出及职责，再分节展开具体构造。抽象接口的规定与具体实现的定义各有位置。

### 同时呈现依赖与选择

- 按实际依赖组织构造：已知输入、必要的内部定义、可选函数、完整返回值。标题应说明本节构造的对象或完成的任务。
- 同级候选应完成同一项任务，例如返回同型记忆描述或给出发送控制。共享准备、内部辅助量与完整候选使用不同层级。
- 共同定义放在所有使用者之前、最接近它们的共同章节中。若特征或尺寸供多个候选使用，应从最初使用它的候选中提取出来。
- 局部评分、区域评分、发送分配等不同选择位置分别说明，并交代合法组合。依赖可以分支；某候选不使用的量无需伪装成其必要步骤。
- 每个构造最后组装上游要求的完整结果。共同的组装步骤放在全部候选所属的层级，读者应能从选定候选一路读到返回值。

例如，在已有接口中，节点描述是 Describe 的返回值；局部评分和区域评分可以是构造及使用描述时的内部量。介绍这些量时说明其所属步骤，避免靠文末的对应表让读者回头重建关系。

又如，若若干 Attention 发送规则共用份额函数，应先说明这组规则的共同任务，在其共同章节中定义份额，再并列给出各发送公式。约束优化分配作为另一组完整候选组织；具体方法的数学关联另行说明。

这些例子展示组织方法。章节数量、标题和具体构造依文档内容选择；简短定义可以在同一自然段中完成。

### 从整体进入细节，再回到整体

展开候选前，先交代共同任务、输入输出及其后续用途。可以先声明各候选函数的名字和职责，再给出具体定义；依赖公式的推论和直观解释在定义后展开。

区分共同准备、候选内部和共同收尾。候选专用的尺寸、条件和性质留在相应定义内；共同的结果组装、性质和比较放在候选组之外。较长构造可将“候选函数”和“所选结果与性质”设为同级小节，并把具体候选放入前者。简短候选可在一个公式或有明确结束位置的列表中并列，随后讨论共同结果。章节层级或排版须显示读者何时离开最后一个候选。

收尾应将细节重新接回整体：所选函数如何给出共同输出，两种构造从公式上可见的差异是什么，结果随后进入哪一步。只保留对当前阅读有帮助的内容；无需重复全部定义，也无需在每个分支重复同一收尾。

## 数学、符号与接口

- 同一对象沿用同一术语和符号。新名字对应实际的新区别；介绍区别时说明与已有定义的关系。数学函数、配置名和实现接口保持可直接核对的对应。
- 区分规定接口、实现接口和使用接口。下游使用时引入所需输入输出；实现时给出完整构造。必要复现服务于当前推导，详细定义保持明确来源。
- 重要的模块组合关系应在数学表达中可见。可用参数化函数族区分组成模型时选定的函数与一次求值的输入，说明部件如何参与计算，并约定绑定后的简写。按实际需要展开依赖，避免为同一职责另造近义函数。
- 引入量时交代其数学含义和用途。上界说明约束哪个节点或分量；“可变”说明随输入、参数还是可行集中的选择而变。尽量使用具体量和公式表达。
- 结构、顺序、状态快照、返回元组和边界处理都是语义的一部分。重排正文时一并核对；共同公式在不同状态上求值可能得到不同结果。
- 局部特化的附加约束明确归属于该特化。相同签名说明可以连接；组合是否有效、具有什么性质，仍由相应条件决定。
- 将共同假设、候选条件、实例参数与例子取值分开。连续性、稀疏性、传播和收敛结论写清比较对象、参数、时间范围及必要条件；局部结论到整网结论需要相应论证。
- 区分数学结论、设计直觉与实验观察。教材可解释从公式直接可见的结构和性质；训练、性能等经验性优劣及外部研究依据放在相应研究文档中。例子帮助理解定义和边界，其结论适用范围须明确。

## 简洁与解释的取舍

使用具体、直接的句子。教材以正面陈述定义和行为，避免用“不是……而是……”反复界定立场。必要的数学对比应说明条件和结果的具体差异。

保留连接定义所需的解释。重复出现同一对象时，让读者知道本处是在引入输入、实现函数、应用结论还是说明性质；删除没有新增作用的重复推导和总结。短小的直接推论可紧随定义，较长导数、极限分析和证明在完整构造之后展开。

先改善正文，再调整入口与索引。目录、文件名和标题反映实际内容；避免新增只作转向的文档或没有用途的空目录。现有组织已经清楚时保留它。

## 公式与纸面排版

兼顾 Obsidian 阅读与 A4 导出。固定本次核验的页面、页边距、字号和渲染方式，按实际正文宽度检查公式及编号；横向滚动只解决屏幕浏览，打印时的 `overflow: visible` 也不能使超宽公式自动适配纸张。

- 按数学结构换行。多个并列定义按依赖次序纵向排列；单个长等式在等号、加减项或推导步骤之间断行。使用 `aligned`、`split` 等环境中的显式行分隔，普通源码换行不产生数学换行。多行环境内也须检查每一行的宽度。
- 保留接口的完整参数、元组顺序、条件和量词。长签名可将函数名、定义域与值域分行；长分段条件可在紧邻正文说明。新增辅助量应有明确数学用途，避免只为纸宽另造名称。
- 一个数学对象或紧密相关的公式组可共用一个编号。单纯换行保持原编号与引用；共同条件放在覆盖全部相关行的位置，避免排版改变读者理解的适用范围。
- 正文与公式保持统一、可读的字号，优先调整结构。宽表、长行内公式和不可断开的名称也要检查；确需横向展开的对象可采用单独的版面安排。
- 渲染后核对字体加载、公式报错、溢出、编号碰撞与分页。源码长度用于筛选，实际 A4 PDF 用于验收。记录核验环境，区分完整导出检查与抽样目视检查。

排版修改后比较数学表达，区分换行、对齐、定界符尺寸等布局变化与数学内容变化；涉及正典时按现有文档检查维护已审阅版本。

## 执行与复核

按任务规模使用下列方法；局部改动检查其受影响的定义和引用，全面治理则完整阅读相关正文及依赖。

1. **确认职责与依赖。** 阅读目标文档及相关上游定义、下游使用；找出接口、内部量、共享定义、候选、返回值和性质的关系。必要时在工作过程中整理依赖，正文只保留帮助读者理解的内容。
2. **先确定结构。** 检查哪些节完成同一任务，哪些是共同准备、候选细节或共同收尾，哪些属于性质或实例。结构问题用重排解决，配以必要的简短导入；提取藏在候选内部的共同定义和结论。
3. **完成构造并审读。** 从读者已知内容出发顺序阅读一套有效组合，再检查其他候选。确认每步知道为何引入该量、最终实现哪个接口，切换候选时无需进入另一候选寻找共同前提。除定义顺序外，还要检查读者能否辨认当前内容的适用范围，以及离开细节后如何回到完整构造。整体重写可先完成一篇具有代表性的文档，验证写法后继续。
4. **核对语义与引用。** 对照修改前后检查函数、类型、条件、状态顺序、返回值及性质范围。若任务涉及数学修正，单独说明变化和理由，并更新受影响的定义、证明、例子及实现对应。章节或公式重编号时同步更新引用。
5. **验证并报告。** 使用适合本次改动的已有检查，再说明修改范围、关键组织调整、数学变化及验证结果。机械检查用于发现结构错误，数学正确性与阅读顺序仍需人工审读。

从仓库根目录可运行现有文档检查：

```bash
python3 20-tide-decentralized-neural-network/tools/check_documents.py
```

检查范围以脚本当前实现为准。最终判断是读者能否沿定义完成构造、分辨候选与条件，并将数学结果对应到实现。
